# LedgerLab API Design

Base path: `/api/v1`. JSON in and out (except CSV upload/download). Interactive documentation is
generated by springdoc at `/swagger-ui.html`; the raw spec is at `/v3/api-docs`.

## 1. Conventions

### Authentication

`Authorization: Bearer <jwt>` on every endpoint except `POST /auth/login`, health probes and the
OpenAPI documents. Missing/invalid/expired token → `401`. Valid token, insufficient role → `403`.

### Tenant scoping

The organization is always taken from the token. No endpoint accepts an organization id for data
access. A resource that exists in another organization returns `404`, never `403`.

### Correlation IDs

Clients may send `X-Correlation-Id` (1–64 chars of `[A-Za-z0-9._-]`); otherwise the server generates
one. The value is echoed in the response header, included in error bodies, written to logs, and stored
on audit events.

### Idempotency

Required (`400 IDEMPOTENCY_KEY_REQUIRED` if missing) on:
`POST /deposits`, `POST /payments`, `POST /payments/{id}/captures`, `POST /payments/{id}/void`,
`POST /payments/{id}/refunds`, `POST /transfers`, `POST /payments/{id}/disputes`,
`POST /disputes/{id}/resolution`, `POST /settlement-batches`.

- Header: `Idempotency-Key`, 8–100 chars of `[A-Za-z0-9_-]`.
- Scope: (organization, operation, key). The same key may be used for different operations.
- Fingerprint: SHA-256 over operation, path resource id, and the canonical JSON of the request
  body (or the uploaded file's SHA-256 plus period). Only the hash is stored.
- Same key + same fingerprint → original status code and body, with `Idempotent-Replayed: true`.
- Same key + different fingerprint → `409 IDEMPOTENCY_KEY_REUSED`.
- Requests that fail (4xx/5xx) roll back, so their key is not consumed and may be retried.

### Errors (RFC 7807)

```json
{
  "type": "https://ledgerlab.dev/problems/insufficient-funds",
  "title": "Insufficient funds",
  "status": 422,
  "detail": "Account 'Ada Lovelace' has 1200 available but 5000 is required.",
  "code": "INSUFFICIENT_FUNDS",
  "correlationId": "4b0f7c3e-…",
  "errors": [{ "field": "amountMinor", "message": "must be greater than or equal to 1" }]
}
```

| Status | Used for | Example codes |
|--------|----------|---------------|
| 400 | Malformed JSON, failed Bean Validation, bad query params, missing idempotency key | `VALIDATION_FAILED`, `MALFORMED_REQUEST`, `IDEMPOTENCY_KEY_REQUIRED` |
| 401 | Missing/invalid token, bad credentials | `UNAUTHENTICATED`, `INVALID_CREDENTIALS` |
| 403 | Role not permitted | `FORBIDDEN` |
| 404 | Unknown id or other tenant's id | `NOT_FOUND` |
| 409 | State conflicts | `INVALID_PAYMENT_STATE`, `IDEMPOTENCY_KEY_REUSED`, `DUPLICATE_SETTLEMENT_FILE`, `DISPUTE_ALREADY_OPEN`, `CONCURRENT_MODIFICATION`, `DUPLICATE_REFERENCE` |
| 422 | Well-formed request violating a business rule | `INSUFFICIENT_FUNDS`, `MERCHANT_INSUFFICIENT_FUNDS`, `CAPTURE_EXCEEDS_AUTHORIZATION`, `REFUND_EXCEEDS_CAPTURED`, `ACCOUNT_NOT_ACTIVE`, `INVALID_ACCOUNT_TYPE`, `SAME_ACCOUNT_TRANSFER`, `INVALID_SETTLEMENT_FILE` |
| 500 | Unexpected | `INTERNAL_ERROR` (no details) |

### Pagination, filtering and sorting

List endpoints accept `page` (0-based, default 0), `size` (1–100, default 20) and
`sort=field,direction` restricted to a per-endpoint whitelist. The primary key is always appended
as a tiebreaker so ordering is deterministic. Response envelope:

```json
{ "items": [ … ], "page": 0, "size": 20, "totalItems": 57, "totalPages": 3 }
```

## 2. Endpoints

Role column: **V** = VIEWER, **O** = OPERATIONS, **A** = ADMIN (higher roles include lower).

### Authentication

| Method | Path | Role | Description |
|--------|------|------|-------------|
| POST | `/auth/login` | public | `{email, password, organizationId?}` → `{accessToken, tokenType, expiresInSeconds, user, organization, role, memberships[]}` |
| GET | `/auth/me` | V | Current user, organization, role, memberships |

### Organization and memberships

| Method | Path | Role | Description |
|--------|------|------|-------------|
| GET | `/organization` | V | Current organization |
| GET | `/organization/memberships` | A | List members and roles |
| POST | `/organization/memberships` | A | Create a user (or attach existing by email) with a role |
| PATCH | `/organization/memberships/{id}` | A | Change role (cannot demote the last ADMIN) |

### Financial accounts and balances

| Method | Path | Role | Description |
|--------|------|------|-------------|
| GET | `/accounts` | V | Filters: `type`, `status`, `q` (name/reference). Sort: `createdAt`, `name` |
| POST | `/accounts` | O | `{type, name, reference}` → 201. Creates the ledger accounts atomically |
| GET | `/accounts/{id}` | V | Account with presented balances per ledger account |
| PATCH | `/accounts/{id}` | A | `{status}` ACTIVE ↔ FROZEN, → CLOSED (only with zero balances) |
| GET | `/accounts/{id}/ledger-entries` | V | Paginated entries for all of the account's ledger accounts, newest first |

### Ledger

| Method | Path | Role | Description |
|--------|------|------|-------------|
| GET | `/ledger/transactions/{id}` | V | Journal with all entries |
| GET | `/ledger/integrity` | V | Verifies balanced journals, cached vs. derived balances, and the accounting equation for the organization |

### Deposits and transfers

| Method | Path | Role | Description |
|--------|------|------|-------------|
| POST | `/deposits` | O | `{accountId, amountMinor, memo?}` → 201 simulated external deposit |
| GET | `/deposits` | V | Filter `accountId` |
| POST | `/transfers` | O | `{sourceAccountId, destinationAccountId, amountMinor, memo?}` → 201 |
| GET | `/transfers` | V | Filter `accountId` (either side) |

### Payments

| Method | Path | Role | Description |
|--------|------|------|-------------|
| POST | `/payments` | O | Authorize `{customerAccountId, merchantAccountId, amountMinor, reference?, description?}` → 201 (status `AUTHORIZED` or `FAILED`) |
| GET | `/payments` | V | Filters: `status` (repeatable), `customerAccountId`, `merchantAccountId`, `createdFrom`, `createdTo`, `q` (reference). Sort: `createdAt`, `authorizedAmountMinor` |
| GET | `/payments/{id}` | V | Payment with amounts and `allowedActions` |
| GET | `/payments/{id}/events` | V | Timeline (oldest first) |
| POST | `/payments/{id}/captures` | O | `{amountMinor, final?}` → 201 payment |
| POST | `/payments/{id}/void` | O | `{reason?}` → 200 payment |
| POST | `/payments/{id}/refunds` | O | `{amountMinor, reason?}` → 201 refund + payment |
| GET | `/payments/{id}/refunds` | V | Refunds for payment |

### Disputes

| Method | Path | Role | Description |
|--------|------|------|-------------|
| POST | `/payments/{id}/disputes` | O | `{amountMinor?, reason}` → 201. Default amount: full refundable amount |
| GET | `/disputes` | V | Filter `status`. Sort `openedAt` |
| GET | `/disputes/{id}` | V | Dispute with payment summary |
| POST | `/disputes/{id}/resolution` | O | `{outcome: WON|LOST, note?}` → 200 |

### Settlement and reconciliation

| Method | Path | Role | Description |
|--------|------|------|-------------|
| POST | `/settlement-batches` | O | multipart: `file`, `periodStart`, `periodEnd` → 201 batch summary |
| GET | `/settlement-batches` | V | Batches, newest first |
| GET | `/settlement-batches/{id}` | V | Summary with counts per classification |
| GET | `/settlement-batches/{id}/results` | V | Filter `classification` (repeatable), paginated |
| GET | `/settlement-batches/{id}/results.csv` | V | Download all results as CSV |

### Audit

| Method | Path | Role | Description |
|--------|------|------|-------------|
| GET | `/audit-events` | O | Filters: `action`, `targetType`, `targetId`, `actorUserId`, `from`, `to`. Sort `occurredAt` desc |

### Dashboard

| Method | Path | Role | Description |
|--------|------|------|-------------|
| GET | `/dashboard/summary` | V | Totals of customer available/reserved, merchant available/held, payment counts by status, open disputes, recent payments |

### Operations

| Path | Auth | Description |
|------|------|-------------|
| `/actuator/health`, `/actuator/health/liveness`, `/actuator/health/readiness` | public | Probes (details hidden) |
| `/actuator/metrics`, `/actuator/prometheus` | public in dev; restrict at the network edge in production | Metrics |
